# Crypt Games multiplayer service

Current behavior (2026-11-05): five competitive activities are available online; Guardian is solo only and room creation rejects it. Names are entered before joining and rendered above the authoritative controlled player. Cosmetic teams are seeded per room; the menu no longer offers team selection or specials. Crypt Shuffle is a room playlist that rotates activities after all connected players choose Next activity at match results. Dodge completes its best-of-three match before rotation. Shuffle lobbies announce the new activity and epoch before checkpoints, and the normal asset-loading gate runs before play.

Run `npm run dev:cryptball:online` for both the local game and service. A hosted static game must have `VITE_CRYPTBALL_SERVER` set to a running TLS/WSS service and its origin included in `CRYPTBALL_ORIGINS`. No public service is provisioned in this repository. Without an explicit endpoint, only loopback hosts use port 2567; other hosts display a configuration message instead of trying an arbitrary website port.

The following deployment/transport notes include historical mode integration details. The current availability policy above supersedes historical Guardian-online and team-special descriptions.

Run `npm run dev:cryptball:online` from the repository root for both the game (port 4223) and service. To run only the service, use `npm run dev:cryptball:server`. The local port is 2567. Set `VITE_CRYPTBALL_SERVER` in the browser build to its WSS origin for deployment. Offline modes make no network requests.

Select Cryptball (combat arena), Cryptkick (soccer), Rift Volley (volleyball), Cryptcheck · Hockey, Crypt Dodge, or Crypt Guardian before choosing Solo match, Practice, Quick Play, or Play with friends. All six modes use the same four-player authority and transport. A room keeps its sport through countdown, play, reconnect and rematch. Quick Play filters by sport, build and protocol; omitted sport defaults to Cryptball before matchmaking. Unknown sports are rejected. Private invite links include the room ID and sport. Entering a bare room code discovers the room sport from its authoritative lobby/checkpoint; an explicitly mismatched sport in a direct protocol join is rejected.

Crypt Guardian treats all four athletes as allies while retaining stable legacy seat IDs and cosmetic club slots. One ready human may manually start with three bots; competitive modes still require at least two ready humans online. The room ID determines the encounter seed and rematches retain it; another room selects another encounter. The normal lobby countdown does not skip the new modes' opening possession/guardian wake phase. Held pass input supports reviving in Guardian; Dodge and Guardian dives remain input edges rather than repeated held commands. Quiet controls, suspension and reconnect preserve the normal server ownership and cancellation policies.

The new modes require wire protocol **12** and checkpoint **14**. Mode state includes life/health, possession/catch state, round or encounter state, boss descriptor/attack/projectiles and cover. Client and server must be built together; the authority source graph supplies the build identity. Full mode snapshots retain the existing 16 KiB hard wire limit. See the [new-mode plan](../../docs/cryptball-dodgeball-arena-plan-2026-11-05.md) for gameplay and [network delivery](../../docs/cryptball-network-delivery-2026-11-05.md) for the timing model and historical performance qualification; the [new-mode delivery](../../docs/cryptball-new-modes-delivery-2026-11-05.md) records current integration evidence.

Six cosmetic identities (Rams, Foxes, Owls, Gators, Bats, Hornets) are independent of numeric sides. `preferredTeamId` may establish an unclaimed side; a conflicting unclaimed default moves, while a claimed opponent is preserved. Teammates adopt their established side. Waiting seated players may send `team {teamId}` for their own side; unknown/duplicate/locked requests return `team-error`. A changed selection clears readiness, and both sides explicitly acknowledge with Ready. Lobby and checkpoint `teamIds` are authoritative, survive reconnect/rematch, and never split the sport queues.

`HOST` defaults to loopback, `PORT` to 2567. `CRYPTBALL_ORIGINS` is a comma-separated allowlist (default local ports 4223/4224 only). Specify the actual static app origin; do not use `*`. `CRYPTBALL_METRICS_TOKEN` enables the private `/metrics` JSON endpoint with bearer authentication. `/healthz` is liveness; `/readyz` fails while draining or overloaded. Terminating a process ends its live matches. Clients get an interrupted-match recovery flow; there is no process migration.

Use Caddy or another TLS proxy for HTTPS/WSS. `Caddyfile.example` illustrates one-region routing. Bind the service privately and permit only proxy traffic. Colyseus issues short-lived seat/reconnection tokens; the browser holds its reload token in sessionStorage and deletes it on explicit Leave. The stock SDK sends the reconnection token in its encrypted upgrade query, so proxy request-query logging must remain disabled/redacted. Private invitation links contain a room ID and public sport ID. Reload tokens are scoped by protocol/build and sport for Quick Play, and by protocol/build and room ID for direct private-room recovery. Never add protocol secrets to invitation links or application logs.

Every room has one 60 Hz authority, at most four catch-up steps per callback, bounded input queues (32 frames/client; the separate future-tick window remains 24 ticks), 90 gameplay inputs/second, 100 total messages/second, and a 64 KiB pending-send disconnect ceiling measured from the server ws socket. Full MessagePack checkpoints carry sport, tick, epoch, ownership, RNG and per-client ack together at 20 Hz. Wire protocol 14 requires a matching sport ID in lobby/snapshot envelopes and simulation checkpoint version 16, including ball height/vertical motion, ground-sport control, Rift Volley rally state, hockey faceoff/check receipts, and complete Dodge/Guardian mode state. Volley height now represents the ball center, with floor contact at its mode-specific radius; older checkpoints are rejected. Client/server build identity is derived from the complete authority dependency graph, including shared engine flight math; older wire/checkpoint builds must refresh together. Lobby state uses ordinary messages; there are no schema deltas to invalidate by skipping a checkpoint. Oversized checkpoints terminate the match explicitly. Keep the 6 KiB target distinct from the 16 KiB hard packet limit.

Clients use the documented scheduled-input fallback, one complete-world predictor and atomic restore/replay. An RTT estimator chooses bounded future input ticks; last-known remote held input is provisional. Replay is capped at 32 ticks and retained local history at 128 entries. Visual correction decays over 65 ms, clamps ball height to the floor, and resets across score/rally/possession transitions. Predicted points and new serves remain hidden until authority confirms the transition. The Colyseus SDK predictor is not active: its acknowledgement-driven reconciliation does not atomically bind independent binary checkpoint messages, especially on input-free ticks.

`SIGTERM`/`SIGINT` disables admission, locks rooms, and waits for rooms to finish or five minutes before closing. During an upgrade, route new admissions to a fresh matching client/server build and retain old assets until draining ends. Keep the previous image for rollback. The supplied Dockerfile is a staging template; pin its image digest in deployment. The current room cap is an initial test cap of 25, not measured hosting capacity. No paid host or public endpoint is provisioned by these files.

Public and private rooms in every sport seat four field players in `[0,2,1,3]` order. Four ready humans trigger countdown. Manual starts fill remaining field positions with bots: Guardian permits one ready human; competitive modes require at least two. Hockey retains its neutral 45-tick faceoff after the shared room countdown, freezing action admission and the match clock until release. Seat assignments survive departures and reconnects. There is no goalkeeper seat or room option.

Before shipping, run four separate browsers through the TLS proxy, exercise 2/3/4-human starts, fifth-arrival rejection or next-room admission, rematch, menu/hidden-tab takeover, reload and disconnect recovery, then apply real link delay/loss outside the application and record RTT, correction/replay measurements and load. Deterministic tests and local socket tests do not establish human-play quality or staging capacity.

The four-player private-room browser test uses two rendered browser clients plus two real Colyseus peers to fill all four seats, start automatically, and reload a field client. Cryptkick, Rift Volley, Cryptcheck, Crypt Dodge and Crypt Guardian also have private-room browser scenarios with two rendered clients and bot teammates, bare-code sport discovery and reload recovery. Together these scenarios cover all six modes; the Guardian scenario also verifies seed preservation on retry. Four simultaneously rendered clients are covered separately by the public-room browser test.

Guardian rooms have two allied seats (`player-0`, `player-1`); one ready human may start with one bot, and two ready humans start automatically. Other modes retain four seats.
